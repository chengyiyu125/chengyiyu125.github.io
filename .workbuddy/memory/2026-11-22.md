## 修正阅读时间显示（.ReadingTime 对中文失效）
- 病因：Hugo 的 `.ReadingTime` = 单词数 ÷ wordsPerMinute(212)，按空白分词；中文无空格，整段被当成一两个词，故永远 1 分钟。字数显示用 `countrunes` 才是对的。
- 未采用 `hasCJKLanguage = true`：它会连带把 `.WordCount`、`.Summary` 截断长度改成“字”维度（summaryLength 70 词 → 70 字），会让列表页摘要大幅变短，属未授权的版式变更。
- 采用方案（仅改 `layouts/partials/post_meta.html`）：`$chars = .Content | plainify | countrunes`，`$mins = ceil($chars / readingSpeed)`，下限 1 分钟，输出「约 N 分钟阅读」；字数复用同一 $chars，避免重复计算。
- `hugo.toml [params]` 新增 `readingSpeed = 400`（字/分钟），可调。校验：聽雪詞 2366 字→6 分钟，二零一七 4813 字→13 分钟，短诗→1 分钟。

## 目录改为宽屏左侧固定侧边栏
- 版面事实：PaperMod `.main` = `--main-width 720px` + `--gap 24px`×2 = 768px 居中，正文文本左边线 = 50% − 360px。左侧余白只在宽屏存在。
- 做法（零正文占位）：`layouts/partials/toc.html` 用 `nav.toc-side > details`；`assets/css/extended/custom.css` 在 `@media (min-width:1280px)` 里把 nav 改为 `position:fixed; right:calc(50% + 392px); width:240px`，脱流后不挤压正文；窄屏回落为原折叠块。
- 宽屏自动展开靠 toc.html 内一段内联 JS（matchMedia ≥1280px → details.open = true），summary 保留可点，无 JS 时仍可手动展开，不破坏降级。
- 坑：`details[open] summary::before` 的优先级高于媒体查询里的覆盖，折叠三角在宽屏去不掉；正解是把三角规则整体塞进 `@media (max-width: 1279.98px)`，而非在宽屏写 `content:none`。
- 验证方式：`python -m http.server` 起 public，Chrome `--headless=new --screenshot --force-device-scale-factor` 截图，再用 PIL 裁剪放大核对细节。
